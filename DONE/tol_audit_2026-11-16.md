## Verdict

Almost all comments are justified. Key points:

1. **#1 (PAF coordinates)**: no bug. The code treats PAF as 0-based half-open, as the spec says.
2. **#8 (agp-tpf-utils)**: not suitable as a dependency. Only the IUPAC complement table is worth borrowing.
3. **#6b (ModDotPlot)**: not directly applicable (it computes k-mer identity from FASTA and does not read PAF). Borrow only the architecture idea.
4. The rest are real improvements; the most valuable are **not loading the whole FASTA into memory (#6a)** and **splitting `io.py` (#7)**.
5. The audit also found issues not raised by colleagues (see "Additional findings"), including a plotting bug and silent skipping of malformed PAF lines.

## #1. PAF coordinates: 0-based or 1-based

**Answer: 0-based, half-open `[start, end)`, per the PAF spec. No off-by-one.**

- `io.py:62-68` (`parse_paf` docstring); values are taken as-is via `int(...)`, no +1/-1. [agent]
- Block length is `end - start` everywhere: `models.py:25`, `alignment.py:71,78,84-85`, `255-259`. [agent]
- `merge_intervals` (`alignment.py:207-226`): the condition `start <= merged[-1][1]` is correct for half-open intervals;
  touching intervals `[0,10)` and `[10,20)` merge without losing length. [agent]
- Block midpoints `(start+end)/2` are the geometric centre of a half-open interval; the reflection `target_length - mid` for `-` blocks is exact. [agent]
- Even under a hypothetical 1-based interpretation the error is at most 1 bp per block, and shifting all midpoints by a constant does not change
  the Pearson correlation. No effect on best-target or RC decisions. [agent]

Suggested (low): state in the `merge_intervals` docstring (`alignment.py:209`) that intervals are half-open.

## #2. print -> logging

About 70 `print` calls in 5 files (cli ~45, assignments 9, io ~8, alignment 4, mapping_table 4); `logging` is not imported anywhere. [agent]

Classes: RESULT (tables, stay on stdout), INFO (progress), WARNING (`--min-coverage ignored`, PAF/FASTA mismatch, sex->autosome,
reassigned, missing from mapping table), ERROR (`sys.exit(1)`). Per-line inventory: `grep -n "print(" src/rename_and_orient/*.py`.

Design:
- `logger = logging.getLogger(__name__)` per module; library code never configures logging; `NullHandler` in `__init__.py`.
- Configure only in `cli.py`: `_setup_logging(verbosity, log_file)`; flags `-v/--verbose`, `-q/--quiet`, `--log-file`.
  Console goes to stderr; INFO as `%(message)s`, WARNING+ with `%(levelname)s:`.
- Tables (`cli.py:130-139`, `io.py:163-170`) move to `report.py` as functions returning strings; `--quiet` does not hide them.
- Drop manual `Warning:` / `ERROR:` prefixes and indentation, otherwise messages read `WARNING: Warning: ...`.
- Errors: replace `sys.exit(1)` inside `_write_and_validate` (`cli.py:152-155`) with an exception caught in `main()`;
  "file not found" checks (`cli.py:175,185`) should use `parser.error()`.
- Version banner (`cli.py:167`) -> `logger.info`. `__version__` is hard-coded in `cli.py:2` and duplicated in `pyproject.toml` [unverified how they are kept in sync].
- Lazy formatting: `logger.info("Reassigned: %s -> %s", a, b)`.

Tests: exactly one breaks, `tests/test_units.py:827-837` (`capsys` -> `caplog`). `test_script.py` does not parse output. Add 2-3 tests (table on stdout, `--quiet`).
User-visible effect: some output moves from stdout to stderr; record it in the CHANGELOG.

Note: some warnings currently go to stdout (`cli.py:219,221`, `alignment.py:338`, `io.py:272,287`) and some to stderr; this is inconsistent.

## #4. Typing and except ("array -> string io t=except")

The "array -> string" comment concerned the **FASTA reader** (`read_fasta`, `io.py:18-52`): the colleague suggests accumulating
sequence lines by string concatenation instead of collecting them in a list.

Current code: `current_seq` is a list of 60-char line strings joined with `''.join(...)` at the end of each record. [agent]
Quick measurement (50 Mb, 833k lines, list of lines already in memory, `tracemalloc`): `list.append` + `join` 0.02 s;
`str +=` 0.17 s (~8x slower; relies on a CPython in-place realloc optimisation that is not guaranteed by the language); `bytearray` 0.22 s.
Peak memory is similar in this micro-benchmark (50-57 MB), but it does not capture the real cost: in `read_fasta` every line is a separate
`str` object (~109 bytes per 60-char line, ~1.8x the data) held in the list until `join`, so the transient peak is ~2.8x the record size.

Conclusion: list + `join` is the idiomatic and fastest pure-Python form, and `+=` is not a clear win. The real saving is not in the accumulation
pattern but in avoiding per-line objects altogether: read the record as bytes (`f.read(nbytes)` from the index, then `translate`/`replace` to drop newlines),
which is what the streaming design in #6a does. Treat this comment as folded into #6a; no separate change needed.
**Confirm with the colleague** that this is what they meant.

Other typing and `except` findings:

`uvx mypy src` [agent]: 13 errors in 3 files.
- Implicit Optional: `alignment.py:13` (`ws`), `alignment.py:125` (`target_prefix: str = None`), `cli.py:127` (`mapping_tsv_path: Path = None`). Medium.
- `determine_best_target` (`alignment.py:269-271`) is annotated `-> Tuple[str, Dict[str,int]]` but can return `(None, None)`. The type lies. Medium.
- `list[int]` passed as `list[float]` (`alignment.py:72,79`) -> use `Sequence[float]`. Low.
- `read_fasta`: unannotated `current_seq = []`, `open_func` inferred as bytes|str. Low.
- `typing.List/Dict/Tuple` (~50 places) with `requires-python >=3.10` -> ruff `UP006/UP035/UP045 --fix`.
- Missing annotations: `cli.py:163 main()` without `-> None`, `read_paf_for_cli`, bare `dict`/`list` in `cli.py:123-126`, `mapping_table.py:29`, `io.py:131`.
- matplotlib has no stubs (optional extra) -> mypy override.

except: no bare/broad handlers. There is `alignment.py:386` (`ImportError`; the message goes to stderr and is easy to miss) and `io.py:152`
(`natural_sort_key`, `except ValueError`, mixes int and `inf` in the key). The list-of-characters + `join` in `reverse_complement` (see #5) is the other "array vs string" spot and is fixed by `translate`.

## #5. reverse_complement via byte translation

Current code `io.py:110-128`: a dict with 10 entries (`ACGTacgtNn`); every other character passes through unchanged. [agent]

Replacement with **identical** behaviour:

```python
_RC_TABLE = str.maketrans("ACGTacgtNn", "TGCAtgcaNn")
def reverse_complement(seq: str) -> str:
    return seq.translate(_RC_TABLE)[::-1]
```

Benchmark, 10 Mb: 0.216 s -> 0.015 s (`str.translate`, ~14x) / 0.008 s (bytes, ~27x). Equivalence checked on 12 strings including mixed case and non-ASCII. [agent]
Memory: the old version temporarily holds a list of 1-char strs (~8x the chromosome size), about 4 GB for a 500 Mb chromosome.

**Owner decision needed:** the current implementation **does not complement IUPAC ambiguity codes** (R, Y, M, K, S, W, H, B, V, D):
`RYK` -> `KYR`, correct is `MRY`. This is a latent bug. Recommendation: extend the table to `ACGTRYMKSWHBVDN` (both cases); a ready table exists in
`agp-tpf-utils/src/tola/fasta/simple.py:3-10` (MIT; copy with attribution). This changes behaviour: needs a test and a CHANGELOG entry.
Existing `TestReverseComplement` tests (`test_units.py:156-178`) pass with either variant.

## #6a. Do not load the whole FASTA into memory

`read_fasta` (`io.py:18-52`) returns `Dict[str,str]` that lives until the end of `main()` (`cli.py:179`).
The length check (`cli.py:148-149`) calls `calculate_genome_length`, which runs **a second `read_fasta`** on the output file while the first dict is still alive. [agent]

Peak memory estimate (arithmetic, **not measured**): 1 Gb ~2 GB resident plus transient peaks; 3 Gb ~6 GB plus peaks. After streaming: ~2-3x the largest chromosome.

Sequences are only needed in `write_fasta`; everything else (`validate_paf_fasta_consistency`, `resolve_chromosome_assignments`,
`build_unloc_mappings`, `load_mapping_table_assignments`) only uses `.keys()`.

Design (stdlib only, no new dependencies):
1. `index_fasta(path)`: single pass in binary mode, `name -> (offset, nbytes, length)`; insertion order = file order; raise on duplicate names
   (today the dict silently keeps the last one).
2. Other functions take `index.names` (accept `Mapping`/`Iterable`).
3. `write_fasta`: same output order (chromosome -> its unlocs -> remaining in file order); records are read by random access, one at a time; RC materialises a single record.
   Write in large blocks (avoid ~50M tiny `write` calls).
4. Output length via streaming count or the sum of what was written.
5. `.gz`: `gzip` has no cheap seek -> decompress to a temp file (`$TMPDIR` on the cluster) or fall back to the current in-memory mode. `indexed_gzip` is an external dependency; do not add it.
6. Keep `read_fasta` public (it is exported from `__init__.py`).

Risks: byte-identical output (empty records and the warnings at `io.py:271-273,286-288`, `\r\n`, `strip()` on line edges, duplicates);
changing the `write_fasta` signature breaks `TestUnlocOrderInOutput` (`test_units.py:620-720`), so keep a dict-accepting wrapper.
A byte-for-byte old-vs-new output test is mandatory.

## #6b. Plotting (ModDotPlot) and export as a separate function

**ModDotPlot is not directly applicable** [agent, from the README; source code not inspected]: it computes k-mer identity (modimizers, ANI) from FASTA, PAF is not mentioned in the README,
there is no documented Python API, it pulls pandas/SciPy/ntHash, and its interactive mode (Dash/Plotly) is marked deprecated. It renders with matplotlib, like we do. MIT licence.
Borrow only ideas: separate compute / render / export; several output formats (PNG/SVG/PDF); a plot-ready table for re-rendering; optional colouring by identity
(`matches/block_len`; `PAFRecord` has `num_matches` and `alignment_length`).

Current state: `plot_chromosome_alignments` (`alignment.py:364-481`, ~120 lines) mixes data preparation, rendering and export; block midpoints are
computed 6 times; the `needs_rc` branches are duplicated (`:435-462`); `matplotlib.use("Agg")` is global; there are no tests for plotting.

Proposed new `plotting.py`:

```python
@dataclass(frozen=True)
class PlotData: ...                       # no matplotlib
def prepare_plot_data(records, mappings) -> list[PlotData]
def render_alignment_figure(data) -> "Figure"     # matplotlib.figure.Figure, not pyplot
def save_figure(fig, path, dpi=120) -> None       # format from the extension
def plot_chromosome_alignments(records, mappings, output_dir, fmt="png") -> list[Path]  # thin wrapper, compatible signature
```

A missing matplotlib raises a dedicated exception; `cli.py` prints the warning. Optionally add `--plot-format {png,pdf,svg}`.
Tests: `prepare_plot_data` without matplotlib, `render` via `importorskip`, save to `tmp_path`, CLI `-P`. Save a reference PNG before refactoring for a visual comparison.

## #7. Module naming (io, assignments)

- **`io.py` (347 lines): the comment is justified (high).** It holds 5 distinct responsibilities: FASTA (read/write/length), PAF (`parse_paf`), sequences
  (`reverse_complement`), name sorting (`natural_sort_key`), reporting (`print_mapping_summary`, `save_mapping_tsv`, `write_chromosome_list`).
  It also shadows the stdlib `io` name (confusing rather than broken for an installed package).
- **`assignments.py`: weakly justified (low).** The name matches its main function; the confusion comes from the closeness of `ChromosomeMapping` /
  `FinalChromosomeAssignment` / `mapping_table.py`. Renaming to `renaming.py` is acceptable but optional; either way add a docstring that explains the distinction.
- `alignment.py` (481 lines) was not mentioned but is also mixed: orientation and plotting should be extracted.

Target layout: `fasta.py` (read/write/length/reverse_complement), `paf.py` (parse + filter + prefix + validate), `report.py` (tables, `save_mapping_tsv`,
`write_chromosome_list`), `orientation.py` (`_pearson_r`, `needs_reverse_complement_by_correlation`), `plotting.py`, `names.py` (+ `natural_sort_key`, `_unloc_output_name`),
`alignment.py`, `assignments.py`, `mapping_table.py`, `cli.py`, `models.py`. `io.py` stays as a temporary deprecated shim emitting `DeprecationWarning`.

Conservative minimum: only `io.py` -> `fasta.py` + `paf.py` + `report.py`.

Impact: the public API goes through `__init__.py` (compatibility preserved by updating the paths); there is exactly one direct import in the repo, `test_units.py:952`
(`rename_and_orient.alignment.needs_reverse_complement_by_correlation`); `pyproject.toml` is unaffected (`rename_and_orient.cli:main`); the README does not mention module names.
The package is published to PyPI, so external direct importers of `rename_and_orient.io.*` are possible [unverified] -> keep the shim for 1-2 releases, bump to 1.3.0.

## #8. agp-tpf-utils (`tola`)

**Recommendation: do not add it as a dependency.** [agent; import checked in an isolated venv]

- Functional overlap is only `reverse_complement` (`tola/fasta/simple.py:9`: full IUPAC table, `bytes.translate`). `tola` has no PAF parser, no `SUPER_Z1`-style suffix parser,
  no `is_unloc`, no plain `read_fasta`; unloc names are only generated (`naming_utils.py:204`), never parsed.
- `FastaIndex` (`fasta/index.py:24`) writes `.fai/.agp/.gzidx` next to the input file (side effects in someone else's directory) and is tightly coupled to `tola.assembly.*`.
- Blockers: **not on PyPI** (404), only `git+https://github.com/sanger-tol/agp-tpf-utils`; PyPI rejects direct-reference dependencies, so publishing rename-and-orient would break
  [rule known, not tested]; `requires-python >=3.11` vs our `>=3.10`; +6 packages (2 with C extensions: `indexed_gzip`, `zlib-ng`; wheels for farm22 not checked);
  `click` is imported in library modules (`file_writers.py:11`, `terminal_table.py:3`); no API stability guarantee.
- The only thing worth taking is the `IUPAC_COMPLEMENT` table (MIT, with attribution) - see #5.
- For discussion: if the team is willing to publish `tola` to PyPI and raise the minimum to 3.11, this can be revisited, but the functional gain would still be small.
